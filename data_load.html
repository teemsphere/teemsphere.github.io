6  Loading data

6.1 Overview

The ems_data() function loads and prepares GTAP database files for use in CGE model runs. It handles the three core GTAP data files (dat, par, and set) and is also used to specify any time steps (for temporally dynamic models) and load set mappings for sets that are read into the model (i.e., not constructed from set operations).

ems_data(
  dat_input,
  par_input,
  set_input,
  time_steps = NULL,
  par_weights = "value",
  ...
)
Argument Type Description
dat_input Character or list Path to a HAR file containing basedata coefficient data, or a dat list from GTAP_convert()
par_input Character or list Path to a HAR file containing parameter coefficient data, or a par list from GTAP_convert()
set_input Character or list Path to a HAR file containing set elements and attributes, or a set list from GTAP_convert()
time_steps Integer vector or NULL Time steps for intertemporal models (see Time steps)
par_weights Character Weighting of parameters under aggregation, "value" (default) or "share", for all parameters or per header (see Parameter weights)
... Named arguments Set mappings for read-in sets (see Loading and specifying sets)

GTAP databases need all three input files (dat_input, par_input, set_input) and the model-specific set mappings; a database held in a single HAR file needs dat_input alone (see below). time_steps is required for intertemporal models.

6.2 Input files

Compatible input files are currently limited to those produced by the Global Trade Analysis Project (GTAP). Although the most recent database releases are proprietary, GTAP has consistently made databases publicly available two versions behind the current release: with GTAP 12 current, GTAP 10 is free.

In order to access the freely available database, users will need to register with GTAP and download the “FlexAgg” format. For GTAP 10 this is accessible under the “GDyn Data Base” entry in the GTAP 10 “Satellite Data and Utilities” section here. For paying GTAP members, the current teems version is capable of handling the “FlexAgg” format for GTAP Databases 9 through 12.

The following command will load data consistent with the standard GTAP model, using broad aggregations for regions, commodities, and endowments. Users will need to specify the location of data ("v7_data/gsdfdat.har" placeholder).

v7_data <- ems_data(dat_input = "v7_data/gsdfdat.har", # basedata coefficients
                    par_input = "v7_data/gsdfpar.har", # parameter coefficients
                    set_input = "v7_data/gsdfset.har", # set elements
                    REG = "big3",
                    ACTS = "macro_sector",
                    ENDW = "labor_diff"
)

Note that the actual names of HAR data files vary according to the GTAP release.

A database held in a single HAR file, such as the ORANI-G basedata.har, is loaded by giving dat_input alone. Every character header with distinct entries becomes a set named after its header, every real header a coefficient dimensioned by the set labels stored in the file, and the data are passed through at full resolution; set mappings do not apply on this route.

orani_data <- ems_data(dat_input = "oranig/basedata.har")

Sets read this way keep the element order of their header in the file; so does any set passed through without aggregation on the GTAP route. Aggregated sets are ordered by their mapping. The order matters to a model that works by position, for example through $POS or a mapping read from a header.

A real header stored without set labels is laid out over the sets declared by the coefficient that reads it, in the file’s storage order. If the header’s size or shape does not fit that declaration, ems_deploy() stops with an error naming the header and the coefficient.

Input Type GTAP v9 GTAP v10 GTAP v11 GTAP v12
dat_input gddat.har gsddat.har gsdfdat.har gsdfdat.har
par_input gdpar.har gsdpar.har gsdfpar.har gsdfpar.har
set_input gdset.har gsdset.har gsdfset.har gsdfset.har

6.3 Set mappings

Set mappings aggregate the fine-grained regions, sectors, and endowments in the GTAP database down to the resolution required for a given model run. The set names used in ... depend on the data format — see the Loading and specifying sets chapter for the full list of internal mappings and instructions for supplying custom CSV mappings.

6.4 Time steps

For temporally dynamic models (e.g., GTAP-RE), time steps must be provided representing t0 plus actual year steps from t0. Time steps can be inputted in either actual year increments or represented as chronological years. Note that if chronological years are used, t0 must correspond with the reference year of the database being used.

The following uses explicit time steps (steps from t0), equivalent to chronological years c(2017, 2018, 2019, 2020, 2021, 2023, 2025, 2027, 2029, 2031, 2033) for a database with a 2017 reference year.

data <- ems_data(dat_input = "v7_data/gsdfdat.har",
                 par_input = "v7_data/gsdfpar.har",
                 set_input = "v7_data/gsdfset.har",
                 time_steps = c(0, 1, 2, 3, 4, 6, 8, 10, 12, 14, 16),
                 REG = "WB23",
                 ACTS = "services",
                 ENDW = "labor_agg"
)

Chronological time steps (with t0 corresponding to the reference year of input data).

data <- ems_data(dat_input = "v7_data/gsdfdat.har",
                 par_input = "v7_data/gsdfpar.har",
                 set_input = "v7_data/gsdfset.har",
                 time_steps = c(2017, 2018, 2020, 2022, 2024, 2026, 2028, 2030),
                 REG = "R32",
                 ACTS = "medium",
                 ENDW = "labor_diff"
)

6.5 Converting formats

GTAP_convert() reads a GTAP database’s HAR files into R at full resolution, without any aggregation, which makes it the easy way to inspect or modify a database. With target, it can also convert a standard GTAP database between the v6.2 and v7 formats, or prepare a GTAP-AEZ, GTAP-E or GTAP-Power database for its model. The returned list can be passed directly to ems_data() or ems_example(). After a conversion, set mappings are specified for the target format, not the original format of the data.

GTAP_convert(
  dat_har,
  par_har,
  set_har,
  target = NULL
)
Argument Type Description
dat_har Character Path to the basedata HAR file
par_har Character Path to the parameter HAR file
set_har Character Path to the set HAR file
target Character or NULL NULL reads the files as they are. "GTAPv6" or "GTAPv7" converts a standard GTAP database to that format (standard GTAP databases only). "GTAP-AEZ", "GTAP-E" or "GTAP-EP" prepares that model’s database, without converting its format

6.5.1 Loading HAR files as arrays

When target is omitted, GTAP_convert() simply parses the HAR files into lists of arrays:

dat <- GTAP_convert(
  dat_har = "v7_data/gsdfdat.har",
  par_har = "v7_data/gsdfpar.har",
  set_har = "v7_data/gsdfset.har"
)

v7_data <- ems_data(dat_input = dat$dat,
                    par_input = dat$par,
                    set_input = dat$set,
                    REG = "big3",
                    ACTS = "macro_sector",
                    ENDW = "labor_diff"
)

6.5.2 Converting between classic (v6x) and standard (v7x) formats

To use the classic model with a v7-format database, or the standard model with a v6-format database, specify target. Format conversion applies to the standard GTAP database only.

A GTAP 12 database converted to v6.2 format for the classic GTAP model:

converted <- GTAP_convert(
  dat_har = "v7_data/gsdfdat.har",
  par_har = "v7_data/gsdfpar.har",
  set_har = "v7_data/gsdfset.har",
  target = "GTAPv6"
)

v6_data <- ems_data(dat_input = converted$dat,
                    par_input = converted$par,
                    set_input = converted$set,
                    REG = "big3",
                    PROD_COMM = "macro_sector",
                    ENDW_COMM = "labor_agg"
)

A GTAP 10 database converted to v7 format for the standard GTAP model:

converted <- GTAP_convert(
  dat_har = "v6_data/gsddat.har",
  par_har = "v6_data/gsdpar.har",
  set_har = "v6_data/gsdset.har",
  target = "GTAPv7"
)

v7_data <- ems_data(dat_input = converted$dat,
                    par_input = converted$par,
                    set_input = converted$set,
                    REG = "AR5",
                    ACTS = "macro_sector",
                    ENDW = "labor_agg"
)

6.5.3 GTAP-AEZ, GTAP-E and GTAP-Power databases

The GTAP-AEZ, GTAP-E and GTAP-EP models read sets and parameters that their databases do not ship in the form the model expects. ems_data() recognises these databases and prepares them on load, so the HAR files can be passed directly. To work with a prepared database in R before aggregation, use GTAP_convert() with target = "GTAP-AEZ", "GTAP-E" or "GTAP-EP"; this prepares the database (generates new headers) but does not convert its format. Conversion between v6 and v7 versions of these databases is not supported.

e_data <- ems_data(dat_input = "e_data/gsdfdat.har",
                   par_input = "e_data/gsdfpar.har",
                   set_input = "e_data/gsdfset.har",
                   REG = "big3",
                   ACTS = "energy"
)

6.6 Data aggregation

Data is aggregated according to type, with non-parameter coefficients summed by target set mappings and weighted averages calculated for the parameters below. A simple mean is applied to parameters not listed below, and to the two base data headers that are not values: DPSM (the sum of the household distribution parameters, 1 in every region) and, in GTAP-E and GTAP-Power data, GSHR (the government share of carbon tax revenue). If custom parameter values are desired, these can be directly loaded in their final format into the ems_model() function, and no aggregation or modification will take place. In the below notation, hat (ˆ) indicates the new parameter value and asterisk indicates the destination set mapping.

6.6.1 Parameter weights

The elasticities are aggregated region by region under the share method, so each aggregated region keeps its own values; the value method follows FlexAgg, which weights the Armington, intermediate-input and value-added elasticities (ESBD, ESBM, ESDC, ESMC, ESBC, ESBV) with world totals and writes one value to every region. Two weighting methods are available through the par_weights argument of ems_data():

  • "value" (default): each member is weighted by the value of its nest, as the GTAP aggregation programs (FlexAgg) do; the formulas are given below. The region-generic parameters (ESBD, ESBM, ESDC, ESMC, ESBC, ESBV) are weighted with world totals and take one value in every region, as FlexAgg writes them; a parameter file that carries them region-specific is first averaged over regions with the same weights.
  • "share": each member is weighted by the value of its CES or CET nest, \(V\), times one minus the sum of its squared input shares \(\theta_k\), \[ w = V\left(1 - \sum_k \theta_k^2\right). \] This is the weight under which the aggregate elasticity reproduces the members’ response to a small change in relative prices. A member whose input shares cannot move carries little weight: a commodity that is almost never imported cannot shift the aggregate import share, whatever its elasticity, and neither can imports bought almost entirely from one source. For a nest with two inputs the weight reduces to \(2 V \theta (1 - \theta)\). Shares are taken over the inputs of the aggregated model (for import sourcing, the aggregated source regions). Where every member of an aggregate has a zero weight, the value weight is used instead; where that is zero too (an activity or endowment a region does not have), the members are averaged. Where such members dominate an aggregate, as oil and gas do in the mining sector of an importing region, the share-weighted elasticity can fall far below the value-weighted one.

A single method applies to every weighted parameter; individual parameters can be set apart by name:

v7_data <- ems_data("v7_data/gsdfdat.har",
                    "v7_data/gsdfpar.har",
                    "v7_data/gsdfset.har",
                    REG = "big3",
                    ACTS = "macro_sector",
                    ENDW = "labor_agg",
                    par_weights = c(ESBM = "share"))

The CDE parameters (INCP, SUBP) are not substitution elasticities and are weighted by private consumption under either method. The nests behind the share weights:

Header Nest Inputs (\(\theta_k\)) Value (\(V\))
ESBD domestic/imported, one per agent domestic, imported purchases by firms, households, government and investment (v6: firms, households, government)
ESBM import sourcing aggregated source regions bilateral imports (VMSB; v6 VIMS)
ESDC, ESMC the v12 CEPII-based Armington set (unread by the shipped models) as ESBD, ESBM as ESBD, ESBM
ESBV primary factors aggregated endowments factor payments (EVFP; v6 EVFA)
ESBT intermediates/value added intermediates, value added intermediate purchases plus factor payments (v6: intermediate purchases, as FlexAgg’s v6-format aggregation does)
ESBC intermediate inputs aggregated commodities intermediate purchases
ESBG government demand aggregated commodities government purchases
ESBI investment demand aggregated commodities investment purchases
ETRQ commodities made by an activity (CET) aggregated commodities make matrix (MAKS)
ESBQ activities making a commodity aggregated activities make matrix (MAKB)
EFVE value added/energy (GTAP-E, GTAP-Power) value added, energy factor payments plus energy purchases
EAEZ land across agro-ecological zones (GTAP-AEZ) aggregated zones land rents

ELFVAEN for fossil fuel mining is recalibrated rather than averaged under either method (see below). The GTAP-E and GTAP-Power CDE parameters over TOPP are rebuilt from the commodity-level SUBP/INCP, the energy node as their private-consumption-weighted mean over the energy commodities, as flexagg’s aggpar_e.tab does; the databases’ own SUBE/INCE headers are not used.

6.6.2.1 Aggregation methods

\[ \hat{\sigma}_{\text{d}_i} = \frac{ \sum_{i}^{i^*} \left( \sigma_{\text{d}_i} \sum_r (vdpa_{i,r} + vdga_{i,r} + vdfa_{i,r} + vipa_{i,r} + viga_{i,r} + vifa_{i,r}) \right) } { \sum_{i,r}^{i^*} (vdpa_{i,r} + vdga_{i,r} + vdfa_{i,r} + vipa_{i,r} + viga_{i,r} + vifa_{i,r}) } \tag{6.1}\]

\[ \hat{\sigma}_{\text{m}_i} = \frac{ \sum_{i}^{i^*} \left( \sigma_{\text{m}_i} \sum_r (vipa_{i,r} + viga_{i,r} + vifa_{i,r}) \right) } { \sum_{i,r}^{i^*} (vipa_{i,r} + viga_{i,r} + vifa_{i,r}) } \tag{6.2}\]

\[ \hat{\sigma}_{\text{va}_j} = \begin{cases} \displaystyle \frac{ \sum_{j}^{j^*} \left( \sigma_{\text{va}_j} \sum_r evfa_{j,r} \right) }{ \sum_{j,r}^{j^*} evfa_{j,r} } & \text{if } j \neq cgds \\ \sigma_{\text{va}_j} & \text{if } j = cgds \end{cases} \tag{6.3}\]

\[ \hat{\sigma}_{\text{t}_j} = \frac{ \sum_{j}^{j^*} \left( \sigma_{\text{t}_j} \sum_{i,r} (vdfa_{i,j,r} + vifa_{i,j,r}) \right) } { \sum_{i,j,r}^{j^*} (vdfa_{i,j,r} + vifa_{i,j,r}) } \tag{6.4}\]

\[ \hat{\gamma}_{i,r} = \frac{ \sum_{i,r}^{i^* r^*} \gamma_{i,r} \sum_{i,r} (vdpa_{i,r} + vipa_{i,r}) }{ \sum_{i,r}^{i^* r^*} (vdpa_{i,r} + vipa_{i,r}) } \tag{6.5}\]

\[ \hat{\beta}_{i,r} = \frac{ \sum_{i,r}^{i^* r^*} \left( \beta_{i,r} \sum_{i,r} (vdpa_{i,r} + vipa_{i,r}) \right) }{ \sum_{i,r}^{i^* r^*} (vdpa_{i,r} + vipa_{i,r}) } \tag{6.6}\]

6.6.3.1 Aggregation methods

\[ \hat{\sigma}_{\text{d}_{c}} = \frac{\sum_{c}^{c^{*}}\left(\sigma_{\text{d}_{c}}\sum_{r} (vdpp_{c,r} + vmpp_{c,r} + vdgp_{c,r} + vmgp_{c,r} + vdfp_{c,r} + vmfp_{c,r} + vdip_{c,r} + vmip_{c,r})\right)} {\sum_{c,r}^{c^{*}} (vdpp_{c,r} + vmpp_{c,r} + vdgp_{c,r} + vmgp_{c,r} + vdfp_{c,r} + vmfp_{c,r} + vdip_{c,r} + vmip_{c,r})} \tag{6.7}\]

\[ \hat{\sigma}_{\text{m}_{c}} = \frac{\sum_{c}^{c^{*}}\left(\sigma_{\text{m}_{c}}\sum_{r} (vmpp_{c,r} + vmgp_{c,r} + vmfp_{c,r} + vmip_{c,r})\right)} {\sum_{c,r}^{c^{*}} (vmpp_{c,r} + vmgp_{c,r} + vmfp_{c,r} + vmip_{c,r})} \tag{6.8}\]

\[ \hat{\sigma}_{\text{va}_{a}} = \frac{\sum_{a}^{a^{*}}\left(\sigma_{\text{va}_{a}}\sum_{r} evfp_{a,r}\right)} {\sum_{a,r}^{a^{*}} evfp_{a,r}} \tag{6.9}\]

\[ \hat{\gamma}_{c,r} = \frac{\sum_{c,r}^{c^{*}r^{*}}\gamma_{c,r}\sum_{c,r} (vdpp_{c,r} + vmpp_{c,r})} {\sum_{c,r}^{c^{*}r^{*}} (vdpp_{c,r} + vmpp_{c,r})} \tag{6.10}\]

\[ \hat{\beta}_{c,r} = \frac{\sum_{c,r}^{c^{*}r^{*}}\left(\beta_{c,r}\sum_{c,r} (vdpp_{c,r} + vmpp_{c,r})\right)} {\sum_{c,r}^{c^{*}r^{*}} (vdpp_{c,r} + vmpp_{c,r})} \tag{6.11}\]

\[ \hat{\sigma}_{\text{t}_{a,r}} = \frac{\sum_{a,r}^{a^{*}r^{*}}\sigma_{\text{t}_{a,r}}\left(\sum_{c} (vdfp_{c,a,r} + vmfp_{c,a,r}) + \sum_{e} evfp_{e,a,r}\right)} {\sum_{a,r}^{a^{*}r^{*}}\left(\sum_{c} (vdfp_{c,a,r} + vmfp_{c,a,r}) + \sum_{e} evfp_{e,a,r}\right)} \tag{6.12}\]

\[ \hat{\sigma}_{\text{c}_{a,r}} = \frac{\sum_{a,r}^{a^{*}r^{*}}\sigma_{\text{c}_{a,r}}\sum_{c} (vdfp_{c,a,r} + vmfp_{c,a,r})} {\sum_{a,r}^{a^{*}r^{*}}\sum_{c} (vdfp_{c,a,r} + vmfp_{c,a,r})} \tag{6.13}\]

\[ \hat{\sigma}_{\text{g}_{r}} = \frac{\sum_{r}^{r^{*}}\sigma_{\text{g}_{r}}\sum_{c} (vdgp_{c,r} + vmgp_{c,r})} {\sum_{r}^{r^{*}}\sum_{c} (vdgp_{c,r} + vmgp_{c,r})} \tag{6.14}\]

\[ \hat{\omega}_{\text{q}_{a,r}} = \frac{\sum_{a,r}^{a^{*}r^{*}}\omega_{\text{q}_{a,r}}\sum_{c} maks_{c,a,r}} {\sum_{a,r}^{a^{*}r^{*}}\sum_{c} maks_{c,a,r}} \qquad \hat{\sigma}_{\text{q}_{c,r}} = \frac{\sum_{c,r}^{c^{*}r^{*}}\sigma_{\text{q}_{c,r}}\sum_{a} makb_{c,a,r}} {\sum_{c,r}^{c^{*}r^{*}}\sum_{a} makb_{c,a,r}} \tag{6.15}\]

6.6.4 GTAP-E, GTAP-Power and GTAP-AEZ parameters

The layer parameters are averaged, except for the following.

The elasticity of substitution between value added and energy, \(\sigma_\text{vae}\) (EFVE), is weighted by the share weight of the value-added/energy nest ("share") or by the value of primary factors and energy inputs ("value"), where \(g\) runs over the energy commodities (COME):

\[ \hat{\sigma}_{\text{vae}_{a,r}} = \frac{\sum_{a,r}^{a^{*}r^{*}}\sigma_{\text{vae}_{a,r}}\,vaen_{a,r}}{\sum_{a,r}^{a^{*}r^{*}} vaen_{a,r}}, \qquad vaen_{a,r} = \sum_{e} evfp_{e,a,r} + \sum_{g} (vdfp_{g,a,r} + vmfp_{g,a,r}) \tag{6.16}\]

For the fossil fuel mining activities (coal, oil and gas) it is instead recalibrated at the aggregate level so that the activity reproduces the target supply elasticity \(\eta\) (SPLY, averaged over all regions), given the cost shares of natural resources (\(s_\text{nr}\)) and of \(vaen\) (\(s_\text{vaen}\)) in the value of output, assuming, as Burniaux and Truong (2002) do, a Leontief top nest and perfectly elastic supply of every input other than the natural resource:

\[ \hat{\sigma}_{\text{vae}_{a,r}} = \frac{\eta_{a}}{1/s_{\text{nr}_{a,r}} - 1/s_{\text{vaen}_{a,r}}} \tag{6.17}\]

The other fuels (p_c, gdt) take \(\hat{\sigma}_\text{vae} = 1\).

The elasticity of substitution between land in different agro-ecological zones, \(\sigma_\text{aez}\) (EAEZ), is weighted by land rents, the primary factor purchases \(evfp_{e,a,r}\) over the zones \(e \in\) AEZS ("value"), or by their share weight across zones ("share").
